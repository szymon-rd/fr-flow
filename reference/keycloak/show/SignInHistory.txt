- signInHistory  definition  accepted
  A user is signed in to a realm with a token when a sign-in of theirs to that realm got the token, while they were enabled and with their password, and no sign-out with the token in that realm came after it.
  why: This is what signing in and out means, said of the history of requests alone, whatever the server keeps: the server's sessions are proven to follow it (sessionsMirrorSignIns).

Formally (as written in Scala)
    signedIn := (r: Term[RealmId], u: Term[String], t: Term[String]) => liveIn(history, Session(t, r, u))

Where it sits
  used by    + realmAccess: "A realm's application accepts a token as a user's, with the user's roles, exactly when the user signed in to that realm and got the token, has not signed out with it since, and is still enabled."
  used by    + noUnauthorizedAccess: "A token is accepted only as a user who signed in to that realm with it, has not signed out since and is still enabled, and only with that user's roles."
  used by    + signedInAreAccepted: "A user who signed in to a realm and got a token, has not signed out with it since and is still enabled, has it accepted there as theirs, with their roles."
  used by    + onlyTheSignedIn: "A token is accepted in a realm only as the user who signed in to that realm with it and has not signed out with it since."

Vocabulary
  history: the requests the server has handled since it started, in order: sign-ins, sign-outs and administrators' changes (the server's event log) (open)
  seed: every realm's accounts as loaded at start: username, salted password hash, whether enabled, realm roles (open)
  signedIn: whether the user signed in to the realm, with their password while enabled, got the token, and has not signed out with it since (defined by signInHistory)
