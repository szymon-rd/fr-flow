- serverRun  definition  accepted
  The server's sessions and accounts now are what its requests led to: from the accounts loaded at start and no session, each request handled in turn.
  why: The server handles one request at a time on the state it stored after the last one (serviceWiring), so its state is the requests of its history applied in turn.

Formally (as written in Scala)
    sessions := (r: Term[RealmId]) => stateAfter(history).sessions.filter(x => x.realm === r)
    account := (r: Term[RealmId], u: Term[String]) => accountOf(stateAfter(history).accounts, r, u)

  used by    + sessionLookup (assumption): "The store's index returns a session it holds under the token in the realm asked, if it holds one, and never one of another realm or token."

Vocabulary
  account: the user's account in a realm, as the server holds it now (defined by serverRun)
  history: the requests the server has handled since it started, in order: sign-ins, sign-outs and administrators' changes (the server's event log) (open)
  seed: every realm's accounts as loaded at start: username, salted password hash, whether enabled, realm roles (open)
  sessions: the sessions a realm has open, as the server holds them now (defined by serverRun)
  step (operation): the server's handling of one request: the state it stores, from the state before it (open)
