+ signedInAreAccepted  claim  accepted
  A user who signed in to a realm and got a token, has not signed out with it since and is still enabled, has it accepted there as theirs, with their roles.
  why: The capability half of the purpose: a server that turned everyone away would meet the safety half alone.

Formally (as written in Scala)
  formula:
    forall((r: Term[Realm.T], t: Term[Token.T]) => forall((u: Term[User.T]) =>
      (signedIn(r, u, t) && enabled(r, u)) implies (accepted(r, t) === some((u, rolesOf(r, u))))))

Where it sits

  uses       - identities (definition): "Realms are named; a user is named by their username in a realm; tokens and roles are strings."
  uses       - signInHistory (definition): "A user is signed in to a realm with a token when a sign-in of theirs to that realm got the token, while they were enabled and with their password, and no sign-out with the token in that realm came after it."

  uses       - referenceTokens (definition): "A realm's application accepts a token as the server's introspection of it answers: a token is a reference to a session the server holds, not a statement the application reads."

Vocabulary
  Realm: an organisation using the server, with its own users and applications (defined by identities)
  Role: what a realm lets a user do in its applications, such as admin (defined by identities)
  Token: what a user gets when signing in, and hands to a realm's applications (defined by identities)
  User: a person with an account in a realm (defined by identities)
  accepted: whom a realm's application accepts a token as, now: the user, and the roles it is told they have, if it accepts the token at all (defined by referenceTokens)
  enabled: whether the user's account in the realm is enabled now (defined by accounts)
  rolesOf: the roles the realm gives the user now (defined by accounts)
  signedIn: whether the user signed in to the realm, with their password while enabled, got the token, and has not signed out with it since (defined by signInHistory)
