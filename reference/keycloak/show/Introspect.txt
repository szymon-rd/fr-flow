+ introspect  contract on introspect  accepted  tested, not proven
  An introspection names the realm asking, and a user enabled there with their roles, only for a session that realm holds under the token; and it names that session's user whenever the user is enabled and the token names no other session there.
  why: Keycloak's introspection endpoint, for one request, so each answer of the running server is checked. The claims carry the user's realm roles, which applications use to authorise.

Formally (as written in Scala)
  post (every call of introspect):
    forall((realm: Term[RealmId], token: Term[String]) =>
        keycloak.introspect(realm, token).forall(c => c.realm === realm && sessions(c.realm).contains(Session(token, c.realm, c.user)) &&
          isEnabled(account(realm, c.user)) && c.roles === rolesIn(account(realm, c.user))) &&
        sessions(realm).forall(x => (x.token === token && isEnabled(account(realm, x.user)) && onlyOne(sessions(realm), x)) implies
          (keycloak.introspect(realm, token) === some(Claims(realm, x.user, rolesIn(account(realm, x.user)))))))
  keeps realmIsolation (proven), showing the rule:
    (realm, token, res) => res
          .fold(List.empty[(RealmId, Claims)])(c => List((realm, c)))

Vocabulary
  account: the user's account in a realm, as the server holds it now (defined by serverRun)
  introspect (operation): the server's answer to a realm's application asking about a token: the claims it is active with, or none (not active) (open)
  sessions: the sessions a realm has open, as the server holds them now (defined by serverRun)
