- crmRun  definition  accepted
  What the CRM holds now, its records, their shares and the shares' expiries, is what its history led to: from empty, each write saved by the write side, the rows about its record replaced by those it stored, and each run of the expiry job, in turn.
  why: Nothing else changes the CRM: users write through the write side, and the job ends shares, one at a time, each on what the last left (writeSideWiring, expiryJob); the database replaces the rows about the written record and nothing else (storeEdits). So the store searches read is the one writes made, and it follows what users asked (storeMirrorsRequests). The running read side reads these tables from the database, and the event log is this history (readSideWiring).

Formally (as written in Scala)
    store := runOf(history).records
    shares := runOf(history).shares
    expiries := runOf(history).expiries

Vocabulary
  expire (operation): a run of the expiry job at a time (in seconds) on a store: the store it leads to (open)
  expiries: the times until which the CRM's shares are given, as it holds them now (defined by crmRun)
  history: the CRM's history since it started empty: every write the write side saved and every run of the expiry job, in order (its event log) (open)
  save (operation): the write side: a write applied to the store the database holds, the rows about its record stored; it returns those rows as read back (open)
  shares: the shares the CRM holds now (defined by crmRun)
  store: the records the CRM holds now (defined by crmRun)
