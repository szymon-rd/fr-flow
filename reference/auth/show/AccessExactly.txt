+ accessExactly  claim (a root)  accepted
  A user gets access to a resource exactly when they are signed in and authorized for it.
  why: The idea says no one may access what they are not authorized to; and authorization is what lets a signed-in user in, or the system would serve no one. Who is authorized, and how a user signs in, the domain says below.

Formally (as written in Scala)
  formula:
    forall((u: Term[User.T], r: Term[Resource.T]) => access(u, r) === (signedIn(u) && authorized(u, r)))

Where it sits
  uses       - identities (definition): "Users are named by ids, and resources are paths."
  uses       - requests (definition): "A user has access to a path when some request for it is admitted on their behalf."
  uses       - sessionTable (definition): "A user is signed in when some session token was issued to them."
  uses       - grantTable (definition): "A user is authorized for a path when a grant names that user and that path."

Parts: together they make it (proven: auto)
  + tokenNamesHolder  needed: "A request is admitted only on behalf of the user its token was issued to."
  + accessNeedsGrant  needed: "A request is admitted on behalf of a user only if a grant names that user and the path."
  + grantLetsIn  needed: "A request whose token was issued to a user with a grant for the path is admitted on their behalf."
  clash: Lean found no proof that the parts contradict each other (a try)

Vocabulary
  Resource: something a user may want to access (defined by identities)
  User: a person who uses the system (defined by identities)
  access: whether the system lets the user access the resource (defined by requests)
  authorized: whether the user is allowed the resource, by whatever rule the system adopts (defined by grantTable)
  signedIn: whether the user has signed in, so can present who they are (defined by sessionTable)
