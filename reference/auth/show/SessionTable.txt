- sessionTable  definition  accepted
  A user is signed in when some session token was issued to them.
  why: Users identify themselves with tokens they receive at login; the session table records which token was issued to whom. How tokens are issued is not modelled.

Formally (as written in Scala)
    signedIn := (u: Term[UserId]) => exists((t: Term[String]) => sessions(t) === Some(u))

Where it sits
  used by    + accessExactly: "A user gets access to a resource exactly when they are signed in and authorized for it."

Vocabulary
  sessions: the session table as stored when the request is decided: a token to the user it was issued to at login (open)
  signedIn: whether the user has signed in, so can present who they are (defined by sessionTable)
